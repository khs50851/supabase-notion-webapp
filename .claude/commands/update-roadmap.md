# Claude 명령어: Update Roadmap

`docs/ROADMAP.md`에 적힌 Task 목록을 실제 코드베이스·`/tasks` 문서와 대조해, 이미 완료된 항목의
체크박스(`[ ]` → `[x]`)와 Task 상태 표시(❌/🟡/⚠️/✅)를 갱신합니다. 코드는 수정하지 않고
`docs/ROADMAP.md`(필요 시 관련 `tasks/*.md`)만 갱신합니다.

## 사용법

```
/update-roadmap
```

인자 없이 전체 로드맵을 점검하거나, 특정 범위만 볼 때는 `/update-roadmap Task 009` 처럼 대상을 지정합니다.

## 프로세스

1. `docs/ROADMAP.md`를 처음부터 끝까지 읽고, 각 Task의 상태 표시(✅/⚠️/🟡/❌), "수락 기준", "구현 단계"
   체크박스, "테스트 체크리스트(Playwright MCP)" 항목을 전부 목록화합니다.
2. Task별 "관련 파일"에 나열된 실제 파일을 Read/Grep/Glob으로 대조합니다.
   - **구현 단계 체크박스**: 코드가 실제로 존재하고 문서에 적힌 대로 동작하는 구조인지 확인되면 체크
   - **수락 기준 체크박스**: `npx tsc --noEmit` / `npm run lint`처럼 지금 이 자리에서 재현 가능한
     항목은 Bash로 직접 실행해 통과 여부로 판단
   - **테스트 체크리스트(Playwright MCP) 항목**: 코드 존재만으로 체크하지 않습니다. 이 세션에서
     Playwright MCP로 실제 시나리오를 수행해 통과를 확인한 경우에만 체크하고, 그렇지 않으면 미체크로
     남깁니다(추측 금지 — Supabase 프로젝트 미연결 등으로 실행 자체가 불가능한 경우도 미체크 유지)
3. `/tasks/XXX-*.md`에 해당 Task 문서가 있다면 같은 방식으로 대조하고, ROADMAP.md와 tasks 문서의
   상태가 어긋나 있으면 함께 정리합니다.
4. 대조 결과를 바탕으로 `docs/ROADMAP.md`를 Edit로 갱신합니다.
   - 완료가 확인된 체크박스만 `[x]`로 변경 (근거 없는 체크 금지)
   - Task 제목 옆 상태 표시를 실제 상태에 맞게 조정 (예: 코드는 끝났지만 사용자 액션/실검증이 남았으면
     기존 컨벤션대로 ⚠️ 또는 🟡 유지, 모든 체크리스트가 실제로 통과했을 때만 ✅)
   - 문서 상단 "현재 코드베이스 상태" 표, "기능 ID ↔ Task 매핑", "진행 현황 요약", "다음 착수 작업"도
     바뀐 상태에 맞춰 함께 갱신
5. 변경 후 무엇을 체크했는지, 무엇을 왜 체크하지 않고 남겨뒀는지 요약해 보고합니다.

## 판단 기준 (중요)

- **코드 존재 ≠ 완료**: 파일이 있고 `tsc`/`lint`가 통과해도, 해당 Task의 수락 기준이 "실제 연결
  검증" 같은 런타임 동작을 요구하면 그 부분은 별도로 확인되기 전까지 미체크로 남깁니다.
- **체크를 되돌리는 것도 갱신입니다**: 코드가 삭제/변경되어 이전에 체크됐던 항목이 더 이상 사실이
  아니면 `[x]` → `[ ]`로 되돌립니다.
- **애매하면 미체크 + 사유 기록**: 확실히 판단할 근거가 없는 항목은 체크하지 말고, 보고 시 "확인
  불가 사유"를 함께 남깁니다.

## 출력 포맷

```
### Task <번호>: <제목>
- ✅ 체크함: <항목> — <근거>
- ⏸️ 미체크 유지: <항목> — <사유>
- 🔁 되돌림: <항목> — <사유>
```

Task별 상태 표시가 바뀐 경우 마지막에 "상태 변경 요약"으로 한 번에 정리합니다.

## 참고사항

- 코드를 임의로 수정하지 않고 `docs/ROADMAP.md`(및 관련 `tasks/*.md`)만 갱신
- Playwright MCP 실행 없이 테스트 체크리스트 항목을 체크하지 않음
- `docs/ROADMAP.md`의 기존 표 구조·이모지 컨벤션(✅/⚠️/🟡/❌)을 그대로 유지
