## 범위 밖으로 남긴 것 (의도적)

- Supabase 업서트(캐시 테이블 갱신)는 Task 006(Supabase 프로젝트 생성)이 실제로 완료된 후의
  작업이라 이번 라운드에서 제외했다. 현재는 매 요청마다 노션에서 직접 조회한다.
- 항목(Items) relation이 페이지당 25개를 넘는 경우의 페이지네이션은 다루지 않음
  (`lib/notion/quotes.ts` 주석에 명시된 기존 스코프 결정을 그대로 유지).
- 노션 레이트리밋에 대한 재시도/백오프는 구현하지 않음. 항목 페이지 조회를 순차 처리하는
  것으로 최소한의 완화만 적용.

## 테스트 체크리스트 (Playwright MCP)

- [x] 노션 연동 계정: 대시보드에 실제 워크스페이스의 견적서(INV-2026-09-001, ABC회사,
      ₩5,000,000)가 정확히 표시됨을 확인
- [x] 총 금액이 원화 포맷(`₩5,000,000`)으로 렌더링됨을 확인
- [ ] 100건 초과 데이터 페이지네이션 — 테스트용 노션 DB에 100건 이상 데이터가 없어 실측 불가,
      코드 리뷰로만 확인 (실제 대량 데이터 확보 시 재검증 필요)
- [ ] 노션 측 값 수정 후 재조회 시 변경분 반영 — 매 요청마다 직접 조회하는 구조라 구조적으로는
      항상 최신값이나, 실제 수정 후 재확인은 수행하지 않음

## 변경 사항 요약

`fetchQuotesFromNotion`에 `has_more` 루프를 추가해 전량 수집하도록 했다. 실행 중인 개발
서버에서 `.env.local`에 설정된 실제 Notion 자격증명으로 대시보드가 실제 워크스페이스 데이터를
정확히 표시하는 것을 Playwright MCP로 확인했다.
