# Task 012-1: 핵심 기능 통합 테스트

## 개요

- 기능 ID: F001~F005 (F010은 Supabase 연동 검증이 필요해 이번 라운드 범위 밖)
- 목적: Task 008(수정)~012의 Notion→웹→PDF 파이프라인이 실제로 end-to-end 동작하는지 확인

## 범위 조정 (사용자 지시: "supabase 관련 Task 제외")

Task 006(Supabase 프로젝트/스키마)과 Task 007(Auth)은 실제 Supabase 프로젝트가 없어 검증할
수 없으므로 이번 통합 테스트 범위에서 제외했다. 대신 현재 실제로 동작하는 경로 — **Supabase
미연동 상태에서 `.env.local`의 Notion 자격증명으로 직접 조회하는 경로** — 를 대상으로
Playwright MCP와 `curl`로 실제 흐름을 검증했다.

## 테스트 환경

- 실행 중이던 개발 서버(`localhost:3000`, 사용자가 이미 `npm run dev`로 띄워둔 프로세스)를
  그대로 사용
- `.env.local`에 유효한 `NOTION_API_KEY`/`NOTION_DATABASE_ID`가 이미 설정되어 있어 더미
  데이터가 아닌 **실제 노션 워크스페이스 데이터**로 테스트됨 (견적서 1건, 항목 3건)

## 검증한 흐름 (F002 → F004 → F003 → F005)

- [x] 대시보드 진입 → 노션 연동 배너 없이 실제 견적서 목록(INV-2026-09-001, ABC회사,
      ₩5,000,000) 표시 (F002)
- [x] "공유 링크 생성" 클릭 → 버튼이 "링크 보기"+복사로 전환, 콘솔 에러 없음 (F004)
- [x] "링크 보기" 클릭 → 비로그인 상세 페이지에서 항목 3건(웹사이트 디자인/로고제작/명함디자인),
      소계, 총 금액(₩5,000,000) 정확히 표시 (F003)
- [x] PDF 다운로드 → 유효한 PDF(`%PDF-1.3`), 올바른 헤더, 한글 폰트 임베딩 구조 확인 (F005)

## 발견하고 그 자리에서 고친 버그

1. **Task 008**: Supabase 미연동 분기가 실연결 검증을 건너뛰고 있었음 → 검증을 분기 이전으로
   이동해 항상 실행되도록 수정 (`tasks/008-notion-settings.md` 참고)
2. **Task 010/012**: `lib/dummy/share-tokens.ts`를 평범한 모듈 스코프 `Map`으로 구현했을 때
   Next.js의 RSC 레이어(페이지+서버 액션)와 route 레이어(PDF 라우트 핸들러)가 모듈 인스턴스를
   공유하지 않아, 대시보드에서 막 발급한 토큰을 PDF 라우트가 찾지 못해 404가 발생함을
   실제로 재현·확인했다. `globalThis` 기반 저장소로 교체해 해결 (`tasks/010-share-link.md` 참고)

## 변경 사항 요약

Notion 연동부터 PDF 다운로드까지 실제 노션 워크스페이스 데이터로 전체 플로우가 동작함을
확인했다. 테스트 과정에서 2건의 실제 버그(Task 008 검증 누락, Task 010/012의 Next.js 레이어
간 상태 미공유)를 발견해 즉시 수정했다. Supabase/Auth가 걸린 권한 경계 검증은 Task 006/007
완료 후로 남아 있다.
